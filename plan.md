# Hallucination Detection System
## Implementation Plan

### 1. Project Goal

Build a claim-level hallucination detection system that determines whether statements generated by an LLM are:

- **Supported** by evidence
- **Contradicted** by evidence
- **Insufficiently supported**

The main research goal is to compare different verification approaches and determine which combination provides reliable hallucination detection.

# 8. Phase 5 — Claim Verification

## Method A — Semantic Similarity

Calculate:

```python
similarity(claim, evidence)
```

Example:

```text
0.91 → likely supported
0.32 → likely unsupported
```

Similarity should not be treated as definitive proof.

---

## Method B — NLI

Use:

```text
Premise    = Evidence
Hypothesis = Claim
```

NLI output:

```text
ENTAILMENT
CONTRADICTION
NEUTRAL
```

Example:

```text
Evidence:
The Eiffel Tower was completed in 1889.

Claim:
The Eiffel Tower was completed in 1889.

→ ENTAILMENT
```

Contradiction:

```text
Claim:
The Eiffel Tower was completed in 1895.

→ CONTRADICTION
```

# 9. Phase 6 — Hybrid Hallucination Detector

Combine retrieval and verification signals.

Initial experimental formulation:

```python
score = (
    0.3 * semantic_score +
    0.5 * nli_score +
    0.2 * retrieval_score
)
```

The weights should eventually be learned or tuned using the validation set rather than assumed to be optimal.

Final labels:

```text
SUPPORTED
CONTRADICTED
INSUFFICIENT EVIDENCE
```

# 13. Phase 9 — Error Analysis

Analyze incorrectly classified claims.

Categorize failures into:

1. Retrieval failure
2. Claim extraction failure
3. NLI failure
4. Ambiguous evidence
5. Numerical reasoning
6. Temporal information
7. Entity confusion
8. Multi-hop reasoning

Example:

```text
Claim:
Company X acquired Company Y in 2022.

Retrieved evidence:
Company X acquired Company Y.

NLI:
NEUTRAL
```

If the correct evidence containing the date was never retrieved, this is primarily a **retrieval failure**.

# 17. Recommended Build Order

Do **not** build everything simultaneously.

```text
1. FEVER/HaluEval loader
        ↓
2. LLM answer generation
        ↓
3. Claim extraction
        ↓
4. BM25 retrieval
        ↓
5. FAISS retrieval
        ↓
6. NLI verification
        ↓
7. Similarity verification
        ↓
8. Combined detector
        ↓
9. Evaluation
        ↓
10. Ablation study
        ↓
11. Error analysis
        ↓
12. FastAPI
        ↓
13. React UI
```

### Most important milestone

Before building the UI, we should have this working:

```python
question
    ↓
answer
    ↓
claims
    ↓
evidence
    ↓
NLI
    ↓
SUPPORTED / CONTRADICTED / INSUFFICIENT
```

Then we can run the experiments and produce the **actual research results**.

### Final deliverable

The finished project should have three layers:

```text
                 RESEARCH
                    │
       ┌────────────┴────────────┐
       ↓                         ↓
Detection Experiments       Evaluation
       │                         │
       └────────────┬────────────┘
                    ↓
                 SYSTEM
                    │
             FastAPI Backend
                    │
                 React UI
```

The **research/evaluation layer is the core project**; the FastAPI + React layer demonstrates it as a usable application.
